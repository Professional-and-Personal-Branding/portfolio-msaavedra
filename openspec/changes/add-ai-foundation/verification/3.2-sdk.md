Lo confirmado contra el SDK instalado (`backend/node_modules/@anthropic-ai/sdk`) y contra un servidor

| Pregunta | Resultado |
|---|---|
| Versión de API | El cliente manda `anthropic-version: 2026-10-21` (`client.js`). |
| `messages.parse` | Existe, pero **se descartó**: `parseMessage` lanza `AnthropicError` si el texto no es JSON válido, y un `refusal` o un `max_tokens` (que se facturan) quedarían sin `usage`. Se usa `messages.create` con `output_config.format` y la validación con Zod en el adaptador (la alternativa que D5 ya documentaba), con el orden `refusal` → `max_tokens` → JSON → schema. |
| `zodOutputFormat` con Zod 4.6.7 | `@anthropic-ai/sdk/helpers/zod` compila y arma `{type: "json_schema", …}` con `moduleResolution: node` (sin cambios de tsconfig). |
| `countTokens` | `client.messages.countTokens({model, system, messages, thinking, output_config})` → `input_tokens`; acepta `maxRetries`, `timeout` y `signal` por petición (el conteo se reintenta 2 veces; probado: 529 y luego 200). |
| `output_config.effort` | `'low' | 'medium' | 'high' | 'xhigh' | 'max'`, junto a `format`. |
| `thinking: {type: "between_tools"}` | Está en `ThinkingConfigParam` (sin otros campos); `disabled` también. |
| `maxRetries` y `timeout` | Del cliente y por petición (milisegundos). La llamada facturable va con `maxRetries: 0`: un 529 produce **una** petición (probado). |
| `APIError` | `status`, `headers`, `error` (cuerpo JSON), `type`, `errorCode`, `requestID`. Subclases `APIUserAbortError`, `APIConnectionError` y `APIConnectionTimeoutError`. El cuerpo `error.error` entra tal cual a `classifyAnthropicError`. |
| Id de la petición | `messages.create(...).withResponse()` → `request_id` (el tipo `Message` no trae `_request_id`). |
| Credencial | El SDK 1.9 manda la clave como `Authorization: Bearer <clave>`, **no** como `x-api-key` (el spec del change hablaba de `x-api-key`). La redacción de logs cubre las dos cabeceras (`req.headers.authorization` ya existía; se sumó `x-api-key`, `apiKey` y `ANTHROPIC_API_KEY`). |
| Entorno ambiental | `createAnthropicClient` pasa `apiKey` y `baseURL` explícitos: con `ANTHROPIC_BASE_URL` y `ANTHROPIC_AUTH_TOKEN` definidos en el entorno, el cliente sigue apuntando a `https://api.anthropic.com` con la clave dada (probado). |
